# 技能写作模式与反模式

## 好的模式

### 1. 祈使句指令
用祈使句写——直接命令，不要建议。

```
✅ "从四个来源抓取最新新闻"
✅ "用给定的标题和内容创建新的Wiki页面"
❌ "如果用户问新闻，你应该尝试抓取"
❌ "创建一个wiki页面可能是个好主意"
```

### 2. 带输入/输出的示例

```
## 提交信息格式

**示例1:**
输入：添加了基于JWT的用户认证
输出：`feat(auth): 实现基于JWT的认证`

**示例2:**
输入：修复了支付处理器中的空指针
输出：`fix(payment): 金额为零时解决空指针问题`
```

### 3. 解释为什么，而不仅是做什么

```
✅ "使用wikilink [[像这样]] 连接页面。这让知识图谱能自动创建节点间的边，
    使你的知识库可以导航。"
❌ "始终使用wikilink。这是必须的。"
```

### 4. 清晰定义输出格式

```
## 报告结构
始终使用此模板：
# [标题]
## 执行摘要（1-2句话）
## 核心发现（要点列表）
## 建议（编号列表）
```

### 5. 渐进式披露提示

```
## 大型参考文件
详细API文档见 `references/api_reference.md`。
部署配置见 `references/deployment.md`。
```

## 要避免的反模式

### 1. 全大写必须/始终
```
❌ "你必须始终在做Y之前做X"
✅ "在做Y之前先做X。这样确保输出一致，因为..."
```

### 2. 过于具体的示例
```
❌ "当用户说'在周二下午3点创建一个关于机器学习的页面'时..."
✅ "当用户想创建知识页面时..."
```

### 3. 工具式描述（应该是技能式）
```
❌ "此技能调用web_search工具" （应该是工具，不是技能）
✅ "此技能协调一个多步骤研究工作流，使用web_search、crawl和wiki工具"
```

### 4. 缺少触发上下文
```
❌ "帮助处理文档"
✅ "处理和分析文档（PDF、Word、Excel）。当用户上传文件、询问文档内容、
    需要提取、转换或分析时使用。"
```
