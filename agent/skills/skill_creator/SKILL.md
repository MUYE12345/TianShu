# 技能创建器

用于创建、验证和迭代改进技能的元技能。技能遵循Anthropic标准：SKILL.md + YAML frontmatter + 可选配套资源。

## 核心理念：技能不是工具

技能是**文档化的工作流** — 告诉Agent如何完成特定类型任务的Markdown指令。将它理解为标准操作流程（SOP）。工具是积木，技能是蓝图。

```
技能（做什么） ≠  工具（做一件事）
技能 = 工作流文档 + 可选辅助脚本 + 参考文档
```

## 何时触发

- 用户想创建技能（"帮我创建一个XXX技能"）
- 用户描述想捕获的工作流（"每次做XXX都要好多步骤，帮我整合"）
- 用户想改进已有技能
- 用户询问技能结构或最佳实践
- 用户想验证或打包技能

## 技能创建流程

### 第一步：捕获意图

问这些问题来理解技能应该做什么：

1. **技能要完成什么？** — 获得具体描述
2. **何时触发？** — 什么用户短语/上下文应激活它？
3. **期望输出格式是什么？** — 格式、内容、约束
4. **需要什么工具？** — 列出Agent会用到的工具
5. **是否创建测试用例？** — 客观可验证的技能（文件转换、数据提取、代码生成）受益于测试。主观技能（写作风格、艺术）通常不需要

### 第二步：编写SKILL.md

创建技能目录结构：

```
skill-name/
├── SKILL.md (必需)
│   ├── YAML frontmatter (name、description必需；compatibility可选)
│   └── Markdown指令 (<500行理想)
├── scripts/       (可选) — 确定性任务的可执行代码
├── references/    (可选) — 按需加载的文档
└── assets/        (可选) — 模板、图标、字体
```

#### Frontmatter规范

YAML frontmatter必须遵循这些规则：

- **name**：kebab-case（小写+连字符，最多64字符）。例如："weather-push"、"pdf-analyzer"
- **description**：何时触发 AND 做什么，最多1024字符，禁尖括号
- **compatibility**（可选）：所需工具/依赖，最多500字符
- **allowed-tools**（可选）：技能可使用的工具名称列表

**描述编写指南** — 这是主要的触发机制。让它稍微"主动"一些以防未触发：

```
✅ 好："创建和修改PDF文档。当用户提到PDF、文档生成、表单、发票、合同或需要以PDF格式创建结构化文档时使用。"
❌ 差："帮助PDF创建。"
```

#### 正文写作规范（参考 `references/writing_patterns.md`）

1. **用祈使语气**："抓取新闻"、"创建页面"（而非"你应该..."）
2. **包含示例**：展示输入/输出对，增加清晰度
3. **解释原因**：不只说做什么，要解释为什么
4. **渐进式披露**：
   - 名称+描述：始终在上下文中（约100词）
   - SKILL.md正文：技能触发时加载（<500行）
   - 参考资料：明确需要时按需加载

5. **清晰定义输出格式**：
```markdown
## 报告结构
始终使用此模板：
# [标题]
## 执行摘要
## 核心发现
## 建议
```

### 第三步：验证

在定稿前运行 `scripts/quick_validate.py` 检查：
- SKILL.md存在且有有效的YAML frontmatter
- 名称遵循kebab-case规范
- 描述在长度限制内
- 无意外frontmatter键
- 描述中无尖括号

### 第四步：测试（迭代循环）

1. **创建2-3个测试用例** — 应触发此技能的真实用户输入
2. **用每个测试用例运行Agent**，让其有权访问此技能
3. **评估结果**：
   - 技能是否在应该触发时触发了？
   - Agent是否正确执行了工作流？
   - 输出格式是否符合预期？
4. **根据发现的差距优化SKILL.md**
5. **重复**直到满意（通常2-3轮迭代）

### 第五步：打包（可选）

运行 `scripts/package_skill.py <skill-path>` 创建可分发的 `.skill` 文件（zip格式，含验证）。

## 参考资料

- `references/writing_patterns.md` — 详细写作模式和示例
- `scripts/quick_validate.py` — 自动验证技能结构
- `scripts/package_skill.py` — 将技能打包为.skill文件

## 示例

**例1：创建通知技能**
输入："帮我创建一个技能，每天早晚推送天气提醒到飞书"
流程：面谈 → 确定意图 → 编写SKILL.md → 验证 → 测试 → 优化

**例2：改进已有技能**
输入："wiki-creator技能不太好用，经常不触发"
流程：阅读当前SKILL.md → 用触发查询测试 → 优化描述 → 再次测试
